Build a completely NEW standalone Telegram bot from scratch.
IMPORTANT:
Do NOT inspect or read any existing repository.
Do NOT modify or depend on any existing bot.
Do NOT copy code from an existing project.
This is a completely independent project.
Keep the code simple, stable, and production-ready.
The primary purpose is ONLY Telegram ID detection and duplicate checking.
1. BOT PURPOSE
The bot will be added to Telegram groups.
Whenever the bot receives a group message, it should look for a standalone header named:
ID
Id
iD
id
The matching must be case-insensitive.
If a valid ID value exists after that header, the bot checks whether that ID has already been seen before.
If the ID has never been seen:
Save it.
Do not send any notification.
If the ID has already been seen:
Detect it as a duplicate.
Send a duplicate warning to the group.
The bot must work automatically in EVERY Telegram group where the bot has been added.
There must be NO manually configured group list.
2. NO MONITORED_CHAT_IDS
Do NOT create or require:
MONITORED_CHAT_IDS=
The bot must automatically monitor every group where it is currently a member and receives messages.
Use the incoming Telegram update's chat_id automatically.
If the bot is removed from a group, it naturally stops receiving messages from that group.
Do not require an administrator to register groups manually.
Private chats should not be processed by the ID detection system.
3. ID DETECTION
Recognize these:
ID: 12345
Id: 12345
iD: 12345
id: 12345
Also recognize common separators:
ID - 12345
ID-12345
ID : 12345
ID=12345
The matching must be case-insensitive.
The ID header must be a standalone field/header.
4. DO NOT FALSELY DETECT OTHER FIELDS
These must NOT be treated as valid ID headers:
Client ID: 12345
Telegram ID: 12345
User ID: 12345
Order ID: 12345
Identity: 12345
ID Card: 12345
Only a standalone field named exactly ID should trigger the ID checker.
Use proper boundaries in the parser.
5. MESSAGE WITHOUT ID
If a message contains no standalone ID header:
Example:
Name: Aung
Phone: 091234567
Gmail: test@gmail.com
Then:
Ignore it completely.
Do not query MongoDB.
Do not save anything.
Do not send any response.
The bot should silently continue.
6. EMPTY ID
If the message contains:
ID:
or:
ID -
or:
ID=
or the value contains only whitespace:
ID:
Then:
Ignore the message.
Do not check duplicate.
Do not save anything.
Do not send any notification.
Empty IDs must NEVER be stored.
7. ID VALUE
IDs can be numeric or alphanumeric.
Examples:
12345
000123
ABC123
A-12345
123-ABC
Treat IDs as STRING values.
Never convert IDs to integers.
Very important:
000123
and:
123
must be treated as two different IDs.
8. ID NORMALIZATION
Only perform safe normalization:
Strip leading/trailing whitespace.
Normalize unnecessary surrounding whitespace.
Do NOT:
remove leading zeros
remove hyphens
remove letters
convert to integer
otherwise change the actual ID
Example:
ID: 000123
must remain:
"000123"
9. MULTIPLE ID HEADERS
If a single message contains more than one standalone ID header:
Example:
ID: 12345
Name: Aung
ID: 67890
Treat the message as ambiguous.
For Version 1:
Do not check duplicate.
Do not save anything.
Do not send a notification.
Log the ambiguity if useful.
Do not guess which ID is correct.
10. FIRST-TIME ID
Example:
ID: 12345
If 12345 does not exist in the database:
Save it.
Record when it was first seen.
Record which group it came from.
Record the Telegram message information.
Do not send a notification.
Store useful metadata:
id
first_seen
first_chat_id
first_chat_title
first_message_id
first_user_id
first_username
first_display_name
occurrence_count
Initial occurrence_count should be 1.
11. DUPLICATE ID
If an ID already exists:
Example:
First message:
ID: 12345
Later message:
ID: 12345
The second message is a duplicate.
Send a warning to the current group.
Use a message similar to:
⚠️ DUPLICATE ID
ID: 12345
First Seen:
👤 @Aung
📍 Sales Group
🕐 2026-09-11 14:32
Current:
👤 @KoKo
📍 Sales Group
🕐 2026-09-11 15:08
Total occurrences: 2
Use actual available Telegram information.
If username is unavailable, use display name or Telegram user ID.
12. GLOBAL DUPLICATE CHECK
Duplicate checking must be global across ALL groups.
Example:
Group A:
ID: 12345
Then later:
Group B:
ID: 12345
The second occurrence must be detected as a duplicate.
Do NOT maintain separate ID databases per group.
One ID should be unique globally for this bot.
13. DATABASE
Use MongoDB.
The MongoDB connection must use ONLY:
MONGODB_URI=
Do NOT require:
MONGODB_DATABASE=
The database name should be taken from the MongoDB URI.
Example:
MONGODB_URI=mongodb+srv://username:password@cluster.mongodb.net/id_checker
The database is:
id_checker
Use the database from the URI automatically.
Do not require another environment variable for the database name.

15. UNIQUE INDEX
Create a MongoDB unique index on:
id
This is extremely important.
The bot must be safe when two identical IDs arrive at almost exactly the same time.
Do NOT rely only on:
find → if not found → insert
because this can cause race conditions.
Use MongoDB's unique index and appropriate atomic/error handling.
Two simultaneous submissions of the same ID must never create two primary ID records.
16. DUPLICATE OCCURRENCE
When a duplicate is detected:
Do not create another primary record in id_records.
Record the duplicate occurrence if using id_occurrences.
Increment occurrence_count safely.
Send the duplicate warning.
Make the database operation concurrency-safe.
